# 视频来源：MP4 faststart、转码与 CDN

## 1. 普通 MP4 先做 faststart

MP4 的 moov 包含轨道与采样索引等初始化信息。普通文件的 moov 可能在媒体数据 mdat 后面；支持 Range 的播放器通常会另取文件尾，并不必然下载整部视频，但额外请求和等待会进入起播路径。

faststart 将 moov 移到文件前部。播放器较早拿到初始化信息，可以更直接地继续读取媒体。FFmpeg 提供 `-movflags +faststart`，也提供 qt-faststart 工具。[FFmpeg 封装文档](https://www.ffmpeg.org/ffmpeg-formats.html)

```sh
# 对普通 MP4 重新封装，复制原音视频编码；输出使用新文件名。
ffmpeg -i input.mp4 -map 0 -c copy -movflags +faststart output-faststart.mp4
```

`-c copy` 不重新编码，因此这个命令不是压缩、降分辨率或提升清晰度。faststart 也不会缩短 GOP 或替代 CDN。分片 MP4/fMP4 使用不同组织方式，不能把普通 MP4 的二次移动方案直接套给所有分片输出。

本包把 faststart 作为视频生产链路的检查项；除非对具体线上文件核对了 box 顺序，否则不能宣称该文件已完成 moov 前置。

## 2. 高清与码率一起设计

分辨率决定像素数量，码率影响传输字节，编码与内容决定相同码率下的画质；解码支持决定终端负担。不要用“压缩得越狠越快”代替画质与设备验证。

实际检查：

| 参数 | 与秒开的关系 | 应如何验证 |
|---|---|---|
| 分辨率 | 更高分辨率通常需要更多解码和传输资源 | 读取实际输出宽高，不只读 UI 的“超清”标签 |
| 编码与码率 | 有效率的编码能在保留画质时降低带宽，但终端兼容性不同 | 记录 codec、平均/峰值码率，实机比较画质、首帧与功耗 |
| GOP/关键帧间距 | 影响精确非零位置的前滚解码 | 比较从头起播与精确续播，不混成一种指标 |
| 封装/索引 | 影响初始化所需数据及请求 | 普通 MP4 检查 moov/mdat；HLS 检查清单与初始化段 |
| CDN 与 Range | 影响首字节、跳转读取和缓存复用 | 记录响应、Range/206 行为及网络时间，不只看带宽测速 |

竖屏 1080×1920 属于 1080p 规格。本项目里用户称它为“超清”；公开报告写实际分辨率，避免与 3840×2160 等 4K UHD 术语混淆。一次确认了分辨率，不表示同时确认了码率、转码模板或源素材质量。

## 3. 阿里云、字节/火山引擎等云点播

阿里云点播支持多规格转码、窄带高清等处理，并可通过 CDN 分发转码结果；是否更省带宽，需要按同一素材、输出规格与画质验收。[阿里云点播转码说明](https://www.alibabacloud.com/help/en/vod/user-guide/audio-or-video-transcoding)

字节体系的火山引擎视频点播提供媒资、转码和分发能力；其媒体处理可调整编码、封装、分辨率与码率，CDN 通过加速域名分发缓存内容。[火山媒体处理](https://docs.volcengine.com/docs/video_on_demand/Overviewofmediaprocessing?lang=zh)、[CDN 域名接入](https://docs.volcengine.com/docs/video_on_demand/DomainAccessOverview?lang=zh)

这类服务可以接入现有 Media3 客户端。是否采用供应商播放器 SDK 是另一个技术选择，不能把“使用供应商的点播与 CDN”写成“必须替换为该供应商播放器”。

## 4. 推荐生产链路

```mermaid
flowchart LR
    A[高清源素材] --> B[上传点播服务]
    B --> C[转码与画质验收]
    C --> D{输出封装}
    D -->|普通 MP4| E[faststart 与 Range 检查]
    D -->|HLS| F[清单与分片检查]
    E --> G[存储与 CDN 发布]
    F --> G
    G --> H[后端缓存可用地址与有效期]
    H --> I[目录直出有限窗口]
    I --> J[App 预热与真实首帧验证]
```

HLS 自适应画质还需要服务端生成多码率变体清单和对应媒体；只有一个媒体清单不代表已经具备 ABR。源项目支持 HLS 与 MP4，但具体本轮测到哪一种，以媒体请求与播放器记录为准。

## 5. 交给接入 AI 的完成标准

先检查目标媒体和分发配置，分别报告实际格式、分辨率、码率、索引位置、GOP、加速域名与 Range 支持；无法取得的项标记未核验。产物处理后验证音视频可用、时长/轨道、目标设备播放与首帧，不直接修改原始文件或以供应商宣传数字代替实测。
