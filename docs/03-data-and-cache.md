# 数据库、缓存与本地持久化

## 证据范围

后端部分来自源项目保存的客户端对接说明，未读取后端源码、DDL、执行计划或线上 Redis。以下分别说明“文档记录”和“客户端代码已核对”，避免把缓存策略写成数据库已经完成调优。

## 后端数据对象：文档记录

| 数据 | 记录中的对象 | 与播放链路的关系 |
|---|---|---|
| 剧目 | episode | 目录入口、剧目元数据 |
| 分类与页面结构 | episode_types | 题材、频道、页面楼层/剧单/榜单 |
| 剧目与分类关联 | episode_types_ref | 节点下查询剧目 |
| 观看与追剧等 | ruser_episode_ref | 观看/用户关系；具体字段未核对 |
| 用户与订单 | ruser、ruser_order 等 | 会员与权益；具体查询未核对 |
| 演员与作品 | drama_actor、drama_actor_ref | 演员入口，不是首帧关键路径 |

文档以 `etype`、`path`、`hideflg` 区分页结构与题材，在统一关联模型上装配页面。其价值是减少前端静态路由和不必要的独立模型，不等于自动降低所有 SQL 耗时。

章节表名、列类型、唯一约束、复合索引、真实关联 SQL 未在本次材料中得到核验。**本包不提供可执行生产 DDL。** 接入 AI 应先取得目标查询及执行计划，再讨论按剧目/集号查章节、按分类分页、按用户读取进度等索引；这些是检查方向。

## Redis：后端说明记载

| 内容 | TTL 记录 | 作用 |
|---|---:|---|
| 首页聚合 | 60 秒 | 减少重复聚合查询 |
| 页面树 | 60 秒 | 复用层级装配结果 |
| 分类/频道 | 300 秒 | 减少分类树与逐项统计查询 |
| VOD 完整播放信息与短 URL | 55 分钟 | 减少重复回源 VOD |

说明中把完整播放信息与短 URL 分开存储，批量列表用 MGET 读短值，未命中时并发取源并回写。它解决批量返回地址时逐条读取大 JSON 和重复 VOD 调用的问题。

文档记载 Redis 异常会回源；没有在本次重新验证异常行为、并发上限、防击穿、租户隔离及线上命中率。迁移建议按租户/内容/来源/画质等实际结果维度设计键，不缓存可跨用户误复用的权限结论。回源并发需要预算，不能将文档中的“并发”理解为无限制。

## 客户端 URL 缓存：代码已核对

- 每会话最多 7 项 LRU，上限 1 小时；已识别签名参数的失效前 5 秒与本地上限取较早值。
- 目录地址从原响应接收时刻起算，重复注入不能延长寿命；失败不缓存。
- 同 ID 在途任务合并；普通调用方取消只停止自身等待。
- 窗口变更主动取消过时任务；重试、reset、close 通过代次及任务身份阻止旧结果污染新缓存。
- 账号/会员权限变化重建目录和会话。缓存内部按视频/章节映射，隔离依赖外层会话，不应直接改成无账号边界的全局 Map。

## 媒体缓存与数据库：代码已核对

进程唯一 SimpleCache，100MiB LRU，索引由 Media3 StandaloneDatabaseProvider 管理；缓存目录属于可被系统回收的 cacheDir。不同入口共享同一 DataSource.Factory，首次索引打开在 IO 线程进行。

HLS 清单、加密密钥、分片沿用各自 URI 缓存键；把整集设置成同一个 customCacheKey 会破坏不同资源的区分。签名轮换可能产生新键，不能宣称跨签名永久复用，也不能宣称完整离线下载。

媒体 HTTP 客户端不携带业务 token。鉴权业务请求和视频 CDN 请求保持边界。

## 播放进度：代码已核对

DataStore 按账号和 LIVE/DEMO 模式持久化“章节 ID → 毫秒位置”；会话内也保存位置，用于窗口往返和跨页同步交接。源服务端进度上报主要是章节恢复，不能据本地毫秒记录宣称跨设备毫秒同步。

三类数据要分清：后端业务表、Media3 缓存索引数据库、DataStore 用户状态。没有必要为迁移这套设计额外引入 Room。
