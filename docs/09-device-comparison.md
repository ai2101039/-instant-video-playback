# 两台手机的配置与同包播放实测

2026-10-22先后测试华为nova 7 SE与Mate 40 Pro。两台沿用同一个非调试Performance APK、同一剧第9集、相同0秒/精确8秒起点、相同最近观看卡片入口。当前MP4资源路径摘要一致，视频为H.264、1080×1920、25fps，视频码率约1.55Mbps。

## Mate 40 Pro的实机配置

| 项目 | 核对结果 |
|---|---|
| 机型 | HUAWEI Mate 40 Pro，NOH-AN01 |
| 芯片 | 麒麟9000 |
| GPU | 24核Mali-G78，来自官方规格 |
| 内存 | 8GB档，内核MemTotal约7.31GiB，部分内存由系统/硬件保留 |
| 存储 | 数据分区226GiB，推断约256GB档；开始时可用约57GiB |

机型、芯片、内存、分区、系统与显示设置由实机读取；CPU/GPU和屏幕等标称规格对照[华为官方规格](https://consumer.huawei.com/th/offer/shopee/mate40-pro/specs/)。这是当年的旗舰定位，与上一台nova 7 SE的中端定位区分开；没有将型号定位当作性能测试的替代。

[可机读设备信息](../examples/mate40-pro-device.json)不包含序列号、用户身份、网络地址或账号。

## 从点击到真实首帧

每组各5次。每轮重启进程、通过匹配Debug宿主复位本地进度并清当前视频的本机媒体缓存，再换回同一个Performance包点击。邻集缓存保留，CDN与系统环境未统一控制，不含App启动与测量准备时间。

| 场景 | nova 7 SE / 麒麟820 | Mate 40 Pro / 麒麟9000 |
|---|---:|---:|
| 从头起播中位数 | 666ms | **552ms** |
| 从头起播范围 | 636–706ms | 455–1355ms |
| 精确8秒续播中位数 | 1004ms | **881ms** |
| 精确8秒续播范围 | 980–1066ms | 821–1001ms |

Mate 40 Pro完整样本：

- 0秒：552、1355、562、508、455ms。
- 精确8秒：1001、989、841、821、881ms。

10次真实首帧位置均匹配所设起点，宽高均1080×1920；当前来源就绪前都是一次目录请求，没有额外独立取址。

本轮Mate 40 Pro的典型耗时较低，但样本较少、两机系统/显示设置不同，网络也不是交替控制的严格硬件A/B。不能把中位数差值全部归因于芯片，也不能从多数低于1秒推断所有请求都稳定小于1秒。

## 慢样本保留

1355ms样本中，目录就绪约430ms、当前地址约435ms、prepare约596ms、decoderReady约1218ms、真实首帧约1355ms。目录HTTP头等待约288ms，媒体请求头等待约366ms；加载和解码还会重叠，不能把decoderReady之前的整个间隔当作纯解码耗时。

## 数据与验证边界

Mate 40 Pro另有两项线上媒体设备用例通过：全局5实例、5个不同播放线程、第1–5集真实出帧后共8次双向手势保持目标Player和MediaItem身份。目录当前第3/4集输出1080×1920，回看第2集为478×848，跳回早期窗口时还出现360×640来源。清晰度按实际来源记录，未把所有窗口统称超清。
