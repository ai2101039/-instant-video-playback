# 迁移步骤与完成标准

## 按阶段实施

| 阶段 | 最小改动 | 完成标准 |
|---|---|---|
| 1. 观测 | 加点击、目录、地址、prepare、decoder、frame 事件 | 一次请求能按身份关联到目标真实首帧，日志不含凭据 |
| 2. 请求复用 | 目录直出消费、缓存、在途合并 | 有效命中不重复解析；重试/失效/取消/权限变化正确 |
| 3. 身份复用 | 稳定 Player、MediaItem、输出与页身份 | 相邻往返不无故重建，旧回调不触发当前状态 |
| 4. 有界预热 | 按距离、方向、权限预取 | 有预算、可取消，真实邻帧可晋升，锁集零越权 |
| 5. 当前优先 | 延后邻集 prepare，缓冲饥饿让路 | 当前先得解码机会；首帧后邻集恢复准备 |
| 6. 精确优化 | 仅处理已复现的线程/seek/HTTP 瓶颈 | 功能回归通过，重复实测报告全部样本 |

每步可以单独采用。已有等价实现时复用，不为凑齐文档架构重构。

后端与视频来源也要进入排查：播放地址链路能否由目录直出缩短；VOD 缓存是否批量命中；普通 MP4 是否完成 faststart；视频编码、码率、GOP、CDN 与 Range 是否适合目标设备。视频来源的检查方法见 [封装与分发](08-media-source.md)。

## 必须覆盖的行为

- 首次进入、已缓存再次进入、精确非零位置续播，各自记录真实首帧。
- 窗口内晋升、跳到窗口外、连续多集、反向、快速切换、拖回原页。
- 地址过期/缺失、同集并发请求、用户重试、迟到成功/错误/首帧。
- 锁定集不取媒体，会员生效后刷新目录，切账号隔离旧结果。
- 后台无声、回前台尊重暂停、音频焦点丢失、输出销毁重建。
- 页面交接唯一所有者、唯一发声者，资源回收后能重新播放。
- 若采用 HTTP 优化：精确 Range、读到 EOF、提前关闭、连接复用及真实媒体。

## 资源较弱设备

源项目五槽不是硬性要求。先测目标机型能稳定支持的真实解码输出数，再选择当前 + 一个邻集，或当前 + 双邻集等有界窗口。降低窗口大小、只保留远集数据预热是迁移建议，源项目本次未验证自动动态降级策略。

## 给 AI 的结果约束

“代码已实现”“构建通过”“接口联调”“实机通过”“性能达标”“已发布”分别报告。缺设备时不能写成实机通过；没有真实后端代码时不能写成生产数据库已调整；只有样本中位数不能承诺所有用户一秒内。

若用户只授权分析，交付链路、证据、最小方案与验收方法，不写代码。用户已授权实施时，在现有授权内继续完成，不因本指南额外引入无关审批。
