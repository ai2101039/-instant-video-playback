# 接口：让目录带上可消费的播放窗口

## 已核对的客户端契约

源项目目录接口形态为 `GET /app/v5/drama/sections/{dramaId}`。响应包含完整章节、锁定状态和有限 `playUrls`；每个地址项解析 `serial`、`videoId`、`playUrl`、`current`。目录解析保留响应接收时刻，以约束缓存期限。

分类卡片附带 `firstPlayUrls` 是后端说明中的能力。当前首页播放只使用 sections 的窗口，不再以分类卡片地址作为起播来源。不要把“接口能返回”写成“所有入口都消费”。

## 两种入口的实际差异

| 行为 | 源项目首页 | 源项目详情 |
|---|---|---|
| 初始集 | 唯一 current，否则窗口第一项 | 唯一合法 current，否则已存集号/第一集 |
| 地址映射 | 目录集号匹配；解析仍要求非空 videoId | 集号与 videoId 均匹配 |
| 权限 | 使用最新目录，锁定项不注入来源缓存 | 同左 |
| 缺失或过期地址 | 重取目录；预热无现成地址就跳过 | 允许既有独立地址解析 |

详情的独立解析仍调用源项目旧的 `getPlayInfo` 路径；后端文档已列出 V5 `/play`。这是迁移差异，不能宣称整个源项目播放链路已经完全 V5 化。接入时以目标项目契约为准，明确选定策略。

## 可复用设计

1. 服务端返回当前视频及少量邻集地址，避免客户端对每集串行请求。
2. 客户端先应用权限与章节映射，再注入有效地址；命中后不重复解析。
3. 明确当前目标高于推测目标；等待中的预取可晋升，执行中的同集请求合并。
4. 地址失效、权限变化和普通页面刷新分别处理，不把 URL TTL 当权限 TTL。

## 示例的定位

[directory-response.json](../examples/directory-response.json) 是**归一化示意模型**：保留 playUrls 的关键字段，但顶层结构和章节字段为方便迁移而设计，增加 expiresAt 表达有效期。它不是源接口完整响应，更不是目标后端的现成契约。

接入时逐项确认：业务成功码、剧目/章节/视频 ID 区别、集号连续性、锁定语义、current 歧义处理、签名有效期、请求合并身份、缺失地址回退、账号与租户边界。

## TTL 的跨层问题

后端缓存 55 分钟与客户端缓存 1 小时不天然相容。客户端拿到的可能是服务端缓存了很久的地址。源客户端可识别一部分签名参数，但无法证明识别了所有供应商的过期规则。

接入建议：服务端返回权威失效时间或剩余有效期，客户端按其与本地上限的较早值使用并预留安全余量；拿不到可信有效期时采用保守缓存策略。该建议不代表源接口已实现 expiresAt。
